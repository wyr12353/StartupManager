# 验收清单

写操作会修改真实启动项。所有写操作验收必须在虚拟机快照或专用测试机中执行，并在开始前创建快照。

## 1. 环境

- [ ] Windows 11（当前主力测试版本）
- [ ] Windows 10 22H2（兼容性回归）
- [ ] 标准用户启动一次，确认用户级项可用、系统级项会弹 UAC
- [ ] 管理员启动一次，确认不再重复弹 UAC
- [ ] 确认 WebView2 Runtime 已安装（Win11 自带；Win10 使用安装包 bootstrapper）

## 2. 只读扫描

对照任务管理器“启动应用”、设置 → 应用 → 启动、Sysinternals Autoruns：

- [ ] HKCU Run / RunOnce 条目数量与任务管理器一致（HKCU Run 不应出现重复的 32/64 位行）
- [ ] HKLM Run 的 64 位与 32 位条目分别显示，位数标识正确
- [ ] 启动文件夹快捷方式能解析出目标 exe；公共启动文件夹显示“所有用户”
- [ ] UWP 启动任务与设置页显示一致；组策略控制的项标为只读
- [ ] 计划任务只显示 boot/logon 触发器；Microsoft 任务标为只读
- [ ] 服务页显示自动启动服务，全部标为只读
- [ ] 发布者为空时显示“未知发布者”；系统文件签名显示“签名未验证”而不是“未签名”
- [ ] 有签名但摘要不匹配、证书过期或链不受信的文件显示“签名无效”

## 3. 写操作

每个来源至少验证一个样本：禁用 → 退出并重新登录 → 确认未运行 → 启用 → 重新登录 → 确认恢复。

### 注册表

- [ ] HKCU Run 项：开关后 `HKCU\...\Explorer\StartupApproved\Run` 首字节变为 0x03 / 0x02，时间戳更新
- [ ] HKLM Run 项（无当前用户覆盖）：UAC 授权后 `HKLM\...\StartupApproved\Run` 更新；取消 UAC 时无任何修改
- [ ] HKLM 项已有 HKCU 覆盖时：状态按 HKCU 显示，开关写 HKCU，不弹 UAC
- [ ] HKLM 32 位项：确认写入 64 位视图下的 `StartupApproved\Run32`，并在重新登录后生效
- 实测记录（Windows 11 26300）：HKCU 的 32 位启动项状态写入 `StartupApproved\Run`，`StartupApproved\Run32` 为空；其他 Windows 版本如发现 Run32 有值，需要按可执行文件位数选择覆盖子键
- [ ] RunOnce：开关不可用，提示只读
- [ ] 原值首字节为 0x06/0x07 家族时，切换后保持 0x06/0x07 家族；0x0A/0x0B 同样保留（可用注册表编辑器检查）

### 启动文件夹

- [ ] 用户启动文件夹快捷方式：`StartupApproved\StartupFolder` 的值名与 `.lnk` 文件名一致
- [ ] 公共启动文件夹（无当前用户覆盖）：需要 UAC；取消后状态不变
- [ ] 公共启动文件夹已有 HKCU 覆盖时：写 HKCU，不弹 UAC

### UWP

- [ ] `State` 1 ↔ 2 切换成功，重新登录后行为一致
- [ ] `State` 3/4（组策略）项只读，开关不可用

### 计划任务

- [ ] 非 Microsoft 的 logon 任务可禁用/启用，任务计划程序中的“已启用”状态同步
- [ ] 以当前用户为主体的任务不弹 UAC；以其他用户或组为主体的任务仍需要管理员授权
- [ ] Microsoft 任务只读
- [ ] 无权限任务返回明确错误，不崩溃

### 服务

- [ ] 服务页没有开关；提示“只读”

## 4. 安全与异常

- [ ] UAC 取消：界面提示“已取消管理员授权”，注册表/任务状态不变
- [ ] 无效 ID（例如关闭后重新打开界面再操作旧列表）：返回“请刷新后重试”，不写入
- [ ] 手动破坏 StartupApproved 值（改成 3 字节）：显示状态未知，不崩溃；可恢复
- [ ] 提权 helper 只接受 `set_enabled`，不接受任意路径（代码审查 + 网络/管道观察）
- [ ] 日志不包含完整命令行；actions.jsonl 只包含时间、ID、名称、来源、启用状态和来源位置

## 5. 界面

- [ ] 暗色、亮色、跟随系统三种模式切换正常，重启后保持
- [ ] 中文无方块，字体为 Microsoft YaHei UI
- [ ] 搜索、筛选（全部/已启用/已禁用/第三方/未知发布者）结果正确
- [ ] 详情抽屉展示命令行、发布者、签名、作用域、来源、可执行文件
- [ ] 系统级项与 Microsoft 项操作前有二次确认，取消不写入
- [ ] 快照保存成功；新增/移除/变更项（启用状态、名称、命令行）展示正确
- [ ] 任一扫描来源失败时，保存/对比被拒绝并提示不完整
- [ ] 表头在滚动时保持固定；主题菜单选中项与实际设置一致
- [ ] 100% / 125% / 150% DPI 下表格与抽屉不溢出
- [ ] 键盘 `Ctrl+F`、`F5`、`Esc` 可用
- [ ] 暗/亮登录项截图保存到 `.ui-dump/`（本地验收产物，不随仓库提交；详情与快照截图按需补充）

## 6. 构建

- [ ] `npm run build` 无 TypeScript 错误
- [ ] `cargo test --manifest-path src-tauri/Cargo.toml` 全部通过（集成测试会在 `HKCU\Software\StartupManagerTest*` 下创建并清理临时键）
- [ ] `npm run tauri build` 成功生成 NSIS 和 MSI 安装包
- [ ] NSIS 和 MSI 安装包在干净的 Win10/Win11 虚拟机中均可安装、启动、卸载
- [ ] 安装后 exe 名为 `StartupManager.exe`，开发者工具中 mainBinaryName 生效
- [ ] 程序清单为 asInvoker，普通启动不弹 UAC

## 7. 回滚

- [ ] 虚拟机恢复快照
- [ ] 在真实机器上执行过写操作时，使用 `%LOCALAPPDATA%\StartupManager\snapshots` 中的快照和 `actions.jsonl` 核对并手动恢复
